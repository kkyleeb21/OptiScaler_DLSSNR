# D18 Runtime patch design

This directory is the readable source of `../runtime_patch.json`. The release installer consumes the
compact Base64 manifest; maintainers review and edit `runtime_patch_spec.json`, then regenerate it with:

```powershell
.\Generate-D18RuntimePatch.ps1
.\Generate-D18RuntimePatch.ps1 -Check
```

`Build-D18Release.ps1` runs the check and refuses to package a manifest that differs from this source.
No NVIDIA Runtime binary is stored or generated by the repository. The user's own 310.8-based Runtime
is patched locally, and every touched input range is guarded.

## Contract implemented

- Color and final Output stay at full display resolution.
- Network width is `AlignDown16(outputWidth * ScalingRatio)`.
- Network height is `AlignDown8(outputHeight * ScalingRatio)`.
- Network capacity, active dimensions, `prev_output`, scratch, and dispatch use the same network domain.
- Runtime post-process resolves the network result to the full Output.
- At 3840x2160 and ratio 0.5, the network is exactly 1920x1080.

The patch does not modify the embedded model/cubin, weights, post-process gate, or feature validation.
Sampler experiments are applied separately by OptiScaler at runtime.

## PE layout

The reference DLL has image base `0x180000000`. Its `.text` section maps file offset `0x400` to RVA
`0x1000`, so `.text` sites in this patch use `RVA = file offset + 0xC00`.

The patch adds section `.d16`:

| Field | Value |
| --- | --- |
| RVA | `0x9E42000` |
| Raw file offset | `0x9E28800` |
| Virtual size | `0xAC` (172 bytes) |
| Raw size | `0x200` |
| Characteristics | `0x60000020` (code, execute, read) |

The append hunk begins at the original EOF, file offset `0x9E28670`. It contains 400 zero bytes to
reach file alignment, the 172-byte thunk body, then `INT3` padding to the 0x200-byte raw size. This is
why the guarded append is 912 bytes while executable code is only 172 bytes.

## Code sites

| File offset | RVA/site | Purpose |
| --- | --- | --- |
| `0x17406` | `0x18006` | Call `create_ratio_thunk` instead of forcing CreateFeature ratio 1.0. |
| `0x1741A` | `0x1801A` | Store caller ratio in feature-state X/Y ratio fields. |
| `0x17646` | `0x18246` | Select derived network height for `CreateNetwork`. |
| `0x1764D` | `0x1824D` | Select derived network width for `CreateNetwork`. |
| `0x1774D` | call site `0x1834C` | Redirect `prev_output` creation through the dimension-swap thunk. |
| `0x1778D` | call site `0x1838C` | Redirect state insertion through the dimension-swap thunk. |
| `0x17F1D` | `0x18B1D` | Preserve full active Output W/H separately from network W/H. |
| `0x17F3D` | `0x18B3D` | Call `evaluate_ratio_thunk`. |
| `0x18269` | `0x18E69` | Restore full Output active rect after network sizing. |
| `0x19D6A` | `0x1A96A` | Stop overwriting the retrieved `ScalingRatio` with 1.0. |

The PE-header hunks and every exact expected/replacement byte are documented in
`runtime_patch_spec.json`. `runtime_patch_payload.disasm.txt` is the matching annotated x64
disassembly of `.d16` from the reference D18 output.

## Compatibility and trust boundary

Full-file hashes are recorded for traceability, not used as an allowlist. A community compatibility
Runtime may be accepted only when every D18-touched range contains an explicitly listed unpatched
variant or the full D18 replacement. Unknown bytes at any touched range abort before installation.

Any binary modification invalidates NVIDIA's Authenticode signature. D18 never patches the supplied
source in place and never redistributes it.
